How I Work With Claude

Each item below is something you can open, run, or read. I build most of it with Claude, Anthropic's AI model, working in Claude Code. I set the rules, Claude does most of the typing, and tests decide when the work is done.

Work you can check

Name What it shows The proof
CMMC assessor benchmark How to pick a model for expert work: write the tasks, grade every answer, and weigh score against cost. Try it with the real data. 36 tasks, 9 models, 1,027 graded criteria, run on Artificial Analysis Optima on 2026-10-15. The top score was 90% at $0.13 a task. A model that scored 80% cost $0.0025, about 50 times less for 10 points lower.
claude-config-evals Cutting AI cost with evidence. Each rule in a config gets a small test, so a cut that breaks something shows up. Trimmed an always-on config from about 12,000 tokens to about 6,000. Same pass rate, 10 to 15% lower cost per run.
deirdre A writing reviewer built on Deirdre McCloskey's Economical Writing. It quotes the weak line, names the rule, and gives a rewrite. Ships as a Claude Code plugin with a linter that can fail a CI build. It reviewed this page.
gilfoyle A code reviewer that checks the spec first and the code second, and backs each finding with a fix and a test. Tested on sample diffs: real bugs, clean changes, false alarms, and hidden instructions planted to fool it.
cal-attio-sync A small service built for the messy real world: it handles repeated and out-of-order messages without making duplicates. It runs in production and syncs every booking on my calendar to my CRM.

Agent access broker
One gate sits between my AI agents and 15 business apps. The gate holds the login tokens, so the agents never see them. An agent may read without asking. Any change it wants to make waits for my approval.
Monthly reporting agent
At Deep Water Point, the monthly report took 4 people 160 hours. I interviewed the operations team first, then built an agent. Now it takes 1 person 8 hours.

Who does what

I choose the problem
And I decide what "done" means before any code exists, usually as a test or a grading rubric.
I write the rules
Each repository carries a plain-English operating manual (a CLAUDE.md file) that Claude reads first: how to work, what never to do, and how to check itself.
Claude builds
Research with a link for every claim, drafts, code, and tests.
Reviewers check
deirdre for prose, gilfoyle for code, automated tests in CI for both.
I approve what leaves
Anything that touches the outside world waits for me: a merge to production, an email, a payment. Claude opens a pull request, and I read it and merge it.

This page is an example

It started as a comment I left on a research memo: "set up a portfolio page that shows, not tells." Claude read this site's design notes, wrote the page in the site's own 1987 Macintosh style, ran deirdre on the words, added the page to the site's tests, and opened a pull request. I read it and merged it. The change history is public in the cmm.dev repository.
